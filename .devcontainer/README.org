#+title: Dev Container

* Develop in a container
The dev container gives you Python 3.12, Node.js, MAFFT, and all project
dependencies without installing them on your machine. You need Docker and the
[[https://containers.dev/][Dev Container CLI]]. Install the CLI with ~npm install -g @devcontainers/cli~ if your
package manager does not provide it.

From the repository root, start the container and open a shell:

#+begin_src bash
./enter-dev.sh
#+end_src

The first start downloads the base image and installs dependencies, so it takes longer
than later starts. Once inside, launch both development servers:

#+begin_src bash
./dev-zellij.sh
#+end_src

Open the Vite frontend at http://localhost:3000. It uses the FastAPI server at
http://localhost:8000.

* After changing the frontend
Vite updates http://localhost:3000 as you edit files under ~web/src/~, so normal frontend
work does not require a build or restart.

The dev server is not what a deployment serves, so check anything that depends on the
built site, the export, or the caching rules against the production image instead. It
builds the frontend itself, so run this on the host rather than inside the container and
open http://localhost:8080:

#+begin_src bash
docker compose up --build
#+end_src

* Direct CLI use
You can manage the container without the helper scripts:

#+begin_src bash
devcontainer up --workspace-folder .
devcontainer exec --workspace-folder . bash
#+end_src

The Python environment is already on ~PATH~ in container shells. Dependencies are kept in
Docker volumes named ~<folder>-venv~ and ~<folder>-node-modules~, so they survive a rebuild
and do not create host-specific files in the checkout.

To reinstall dependencies after changing the setup, run:

#+begin_src bash
.devcontainer/post-create.sh
#+end_src

To start clean, stop the container and remove those two named volumes before running
~devcontainer up~ again.
