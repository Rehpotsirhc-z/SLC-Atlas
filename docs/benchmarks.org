#+title: Benchmarks

We benchmarked AtlasForge on the 462-gene SLC atlas, which is a 5.28 GiB dataset
when all optional source files are mirrored locally.

*Note*: All serving and genome-browser benchmarks ran on the same computer using
locally downloaded data. The results compare the tools without internet latency
or differences between hosting providers.

* Key results
- Genome browser :: AtlasForge renders the full view in 0.8–1.1 s from nginx,
  matching igv.js and running about three times faster than JBrowse 2 in this test.
- Genomic data :: Across the tested ranges, genome views read only 90–300 KiB
  from a 309 MiB coverage file. This avoids unnecessary downloads and keeps load times fast.
- Dynamic serving :: Even without a static export, ~atlasforge serve~ returns the
  largest JSON endpoint in 42 ms so the atlas remains responsive.
- Build :: The complete process of fetching, building, and exporting the SLC atlas
  takes about 15 minutes. Since it is one of the largest human gene superfamilies,
  smaller families should generally finish faster depending on internet connection.
- Static serving :: nginx handles 18–66 times as many requests per second as the
  dynamic server, making it the better option for public or high-traffic deployments.
- Hosting :: Core atlas content uses 61 MiB and a full local mirror uses 5.28
  GiB, allowing deployments to reduce storage by streaming optional data from
  source services.

Throughput is the mean number of requests served per second with ten concurrent
connections. The nginx static deployment handles 18–66 times as many requests as the
dynamic server because it returns prebuilt files instead of generating each
response on demand, making the static export the better choice for public or
high-traffic deployments.

* Genome browser
** Render time
Each browser rendered 33 coverage lanes, gene models, and the 17.4-million-variant GWAS track
from the same local server. Values are milliseconds to a visually stable view, shown as
*cold / warm*.

| Visible region span (Mb) | igv.js (ms) | AtlasForge nginx server (ms) | AtlasForge dynamic server (ms) | JBrowse 2 (ms) |
|--------------------------+-------------+------------------------------+--------------------------------+----------------|
|                     0.05 | 777 / 649   | 777 / 699                    | 1,392 / 1,168                  | 2,971 / 3,002  |
|                        1 | 942 / 724   | 937 / 716                    | 1,405 / 1,216                  | 3,665 / 3,359  |
|                       10 | 1,082 / 900 | 848 / 915                    | 1,466 / 1,416                  | 3,212 / 3,056  |
|                       50 | 826 / 632   | 1,082 / 935                  | 1,781 / 1,416                  | 3,372 / 3,268  |
|                      249 | 715 / 586   | 1,149 / 1,099                | 1,796 / 1,499                  | 3,033 / 3,017  |

Across spans from 50 kb to the full length of chromosome 1 (249 Mb), the
AtlasForge static deployment loads in about one second, which is about as fast
as igv.js and 3 times faster than JBrowse 2. The dynamic server takes roughly 0.5–0.7 s
longer than static deployment.

* Build and deployment
** Build time
| Operation      | Time     | Work performed                                   |
|----------------+----------+--------------------------------------------------|
| ~gene_tables~    | 0.23 s   | Convert gene and transcript tables to Parquet    |
| ~conservation~   | 0.39 s   | Build the ortholog matrix and species tree       |
| ~structure~      | 1.25 s   | Build metadata and copy the structure models     |
| ~expression~     | 1.82 s   | Reshape the GTEx expression matrix               |
| ~clustering~     | 11.9 s   | Run protein and codon alignments                 |
| ~browser~        | 81.7 s   | Build genomic indexes and copy the coverage data |
| *Complete build* | *97 s*     | Build data for all views                         |
| Static export  | 5.5 s    | Write responses and copy the binary data         |
| Source fetch   | 12.5 min | Download the source data                         |

Source fetch time depends on network conditions and upstream availability. The GTEx expression
matrix accounts for most of the download.

* Methods
Tests ran on Linux with an Intel Core Ultra 7 255HX, 30 GiB RAM, Python 3.12,
Polars 1.43, Node 20, Playwright 1.62 with Chromium, autocannon 8, nginx 1.24,
igv.js 3.8.5, and JBrowse 2 web 4.3.0.

Browser comparisons used the same data files, locus, viewport, cache state, and
local nginx server. Render time is the median of three runs; other tables use at
least five runs. Remote structure timings reflect the network conditions at the
time of measurement.

See the [[../scripts/benchmarks/README.org][benchmark instructions]] for the harness, raw results, and
reproduction steps.
