#+title: Pipeline files

This page describes the files shared by ~atlasforge fetch~, ~atlasforge build~, and the
running application. Use it to inspect a dataset, replace fetched data, or
identify the pipeline step that creates a file.

* Directory layout
The pipeline keeps downloaded material, human decisions, normalized source data,
and built application data separate:

| Directory                    | Purpose |
|------------------------------+---------|
| ~<data-dir>/cache/~          | Downloads and intermediate files that can be reused by later fetches |
| ~<data-dir>/curation/~       | Files you review and edit to make dataset-specific choices |
| ~<data-dir>/source/~         | Normalized inputs written by ~atlasforge fetch~ and read by ~atlasforge build~ |
| ~<data-dir>/app/~            | Built Parquet tables and binary assets served by the application |

~atlasforge fetch~ does not replace existing curation files. It also skips a completed
fetch step when all of that step's declared outputs already exist. Use ~--step NAME~
to run a step again. If you replace a source file yourself, skip the fetch
step that normally creates it or keep the replacement in place when running
selected steps.

~--step~ also runs ~fetch_hgnc~, which creates the curation files used by the other
steps. If those files already exist, the step reads them without replacing them.

If a step fails, only its dependent steps are skipped. The remaining work continues,
and the command ends with a summary and a non-zero exit status. Run the same command
again to reuse completed work and retry the rest. Set ~ATLASFORGE_TRACEBACK=1~ to include
tracebacks for unexpected errors.

~atlasforge build~ reads only from ~source/~ and writes to ~app/~. Files in ~cache/~ and
~curation/~ are not served directly.

* Curation files
The first ~atlasforge fetch~ creates the following files in ~--curation-dir~, which
defaults to ~<data-dir>/curation/~. Unless ~--no-review~ is set, the command
then pauses so you can review any newly created files.

Blank lines and comment lines beginning with ~#~ are ignored. TSV files must
remain tab-separated.

| File                    | Controls |
|-------------------------+----------|
| ~families.tsv~          | Family keys and display names for the HGNC groups in the atlas |
| ~exclusions.txt~        | HGNC-approved gene symbols to leave out, one per line |
| ~symbol_overrides.tsv~  | Display symbols to use without changing the approved searchable symbols |
| ~species.tsv~           | Species included in conservation and their names in Ensembl, TimeTree, and UCSC |
| ~uniprot_overrides.tsv~ | Manual corrections to the Ensembl gene-to-UniProt mapping |
| ~browser_tracks.tsv~    | Coverage tracks, their labels, grouping, source, strand, resolution, and hosting mode |
| ~browser_gwas.tsv~      | GWAS studies, traits, citations, sources, assemblies, and licenses |

Edit curation files instead of generated source tables whenever a choice has a
matching curation file. For example, correct a UniProt match in
~uniprot_overrides.tsv~, not in the generated ~source/structure/uniprot_map.tsv~.

* Source files
All paths in this section are relative to ~<data-dir>/source/~. Tables are TSV
unless their names specify another format.

** Gene tables
These files define the genes in the atlas and are used by every view.

| File              | Contents | Created by |
|-------------------+----------+------------|
| ~genes.tsv~       | ~id~, ~symbol~, ~name~, ~chromosome~, ~start~, ~end~, ~strand~, ~length~, ~alias~, ~category~, ~family~, ~family_name~, ~function_brief~ | ~assemble_genes~ |
| ~transcripts.tsv~ | ~id~, ~gene_id~, ~name~, ~type~, ~start~, ~end~, ~length~ | ~assemble_genes~ |

The gene coordinates use the Ensembl assembly selected during fetch. Browser
annotations and GWAS studies must use the same assembly.

** Clustering
The clustering build combines sequences, expression values, orthologs, and
family assignments. Some inputs are also used by other views.

| File                 | Contents | Also used by |
|----------------------+----------+--------------|
| ~cds.fasta~          | Canonical coding sequence keyed by Ensembl gene ID | — |
| ~protein.fasta~      | Canonical protein sequence keyed by Ensembl gene ID | Structure |
| ~expression.parquet~ | One row per gene, with ~gene_id~ followed by Float32 TPM columns for each sample | Expression |
| ~sample_tissue.tsv~  | ~sample_id~, ~tissue~, ~tissue_detail~ | Expression |
| ~orthologs.tsv~      | ~gene_id~, ~species~, ~target_gene_id~, identity values, orthology type, and ortholog count | Conservation |

The build creates trees from protein sequence, coding sequence, expression
correlation, ortholog identity, and curated family membership.

** Expression
Expression uses ~expression.parquet~, ~sample_tissue.tsv~, and ~genes.tsv~. Sample IDs
in ~sample_tissue.tsv~ must match the sample columns in ~expression.parquet~.
Expression values are TPM stored as Float32.

** Conservation
Conservation uses the following files together:

| File               | Contents | Created by |
|--------------------+----------+------------|
| ~orthologs.tsv~    | One gene and species comparison per row | ~fetch_orthologs~ |
| ~species.tsv~      | ~species~, ~species_label~, ~taxon_id~ | ~fetch_species_tree~ |
| ~species_tree.nwk~ | Newick tree whose leaf names match the ~species~ column | ~fetch_species_tree~ |

The build adds the reference species and creates both the conservation matrix
and the species tree used by the application.

** Structure
Structure inputs are stored under ~source/structure/~:

| File                   | Contents | Created by |
|------------------------+----------+------------|
| ~uniprot_map.tsv~      | Gene, symbol, UniProt accession and ID, sequence agreement, and matching route | ~fetch_uniprot_map~ |
| ~sequences.tsv~        | UniProt canonical sequence used for residue numbering | ~fetch_uniprot_sequences~ |
| ~features.tsv~         | Topology, binding-site, and ligand annotations with residue ranges | ~fetch_protein_features~ |
| ~structures.tsv~       | AlphaFold and AlphaFill model metadata and URLs | ~fetch_structures~ |
| ~experimental.tsv~     | PDB entry metadata, method, resolution, chains, coverage, and ligands | ~fetch_structures~ |
| ~confidence.parquet~   | Per-residue pLDDT values for models that match the canonical UniProt sequence | ~fetch_confidence~ |
| ~models/<accession>.cif~ or ~.bcif~ | Optional locally hosted predicted models | ~download_models~ |
| ~models/pdb/<entry>.bcif~ | Optional locally hosted experimental models | ~download_experimental_models~ |

Without ~--download-predicted~ or ~--download-experimental~, the application reads
models from AlphaFold DB or RCSB. Locally downloaded models are copied to
~app/structure/models/~ during the build and included in a static export.

** Genome Browser
Browser inputs are stored under ~source/browser/~. By default, each source is limited to
windows around the atlas genes. Use ~--browser-whole-genome~ to retain genome-wide data
instead. Each window uses the gene length as its flank, limited by ~--browser-flank-min~
and ~--browser-flank-max~, and is at least 200 kb wide.

| File                   | Contents | Created by |
|------------------------+----------+------------|
| ~transcripts.bed~      | Transcript models for the retained regions, as BED12 followed by ~gene_id~, ~biotype~, and ~gene_name~ | ~fetch_gene_models~ |
| ~chroms.tsv~           | Chromosome name, length, and role | ~fetch_gene_models~ |
| ~gene_models.tsv~      | Annotation source, version, assembly, license, URL, retrieval date, and fetch flanks | ~fetch_gene_models~ |
| ~coverage.tsv~         | Resolved coverage sources, chromosome checks, binning, hosting mode, and size estimates | ~fetch_coverage~ |
| ~coverage/*.bw~        | Optional local bigWig copies, whole-genome or cut to the merged browser windows | ~slice_coverage~ |
| ~gwas.parquet~         | GWAS variants in the retained regions | ~fetch_gwas~ |
| ~gwas_studies.tsv~     | Trait, citation, source, assembly, license, URL, retrieval date, variant count, and chromosomes | ~fetch_gwas~ |

*** Gene model input
By default, the pipeline downloads the GENCODE release associated with
~--ensembl-release~. Use ~--gene-models-file~ to supply GTF, GFF3, or BED12 instead.
Each format may be gzip-compressed.

GTF is preferred because it stores each required value in a named attribute. The
pipeline groups ~exon~ rows by ~transcript_id~ to construct exon blocks and the
introns between them, and reads ~CDS~ rows for the coding range. It takes the
biotype from whichever of ~transcript_type~, ~transcript_biotype~, ~gene_type~,
~gene_biotype~, or ~biotype~ is present, and the label from ~gene_name~, ~Name~, or
~gene~.  GFF3 is read the same way, with each row naming its transcript through
~Parent~.

BED12 has one free-text ~name~ field, so the pipeline accepts three layouts:

| ~name~ holds                                     | Rest of the identity comes from | Written by |
|--------------------------------------------------+---------------------------------+------------|
| the transcript ID                                | columns 13, 14, 15: ~gene_id~, ~biotype~, ~gene_name~ | this pipeline |
| ~transcript_id___gene_id___biotype___gene_name~  | the name field itself           | other portals in this field |
| the transcript ID alone                          | nothing; gene fields stay empty | ~gtfToGenePred~ then ~genePredToBed~ |

The build compares the start and end coordinates of shared genes. It stops when
fewer than 95% agree, which usually indicates that the annotation and gene table
use different assemblies.

*** Coverage input
Add one row to ~browser_tracks.tsv~ for each bigWig. The source may be an ENCODE
accession, a URL, or a local path. Other coverage formats must be converted to
bigWig before fetch.

For stranded data, use two rows with the same ~track_id~ and set ~strand~ to ~plus~
and ~minus~. Set ~local~ to ~yes~ to create a copy under ~coverage/~, or ~no~ to
let the browser read the source URL directly. Remote servers must support byte
ranges and cross-origin requests.

Slicing and binning are independent. ~--browser-whole-genome~ controls which regions are
retained, while ~--browser-bin~ controls their resolution. When neither slicing nor
binning is requested, the source file is copied without being rewritten.

~--browser-bin~ controls the finest resolution retained in local copies. A source
that is already coarser is left at its existing resolution. Before slicing, the
pipeline estimates the total size and stops if it exceeds ~--browser-max-bytes~.

*** GWAS input
In ~browser_gwas.tsv~, ~source~ may be a GWAS Catalog accession, a local file, or a
directory containing one file per chromosome. Supported files are Parquet or
text separated by tabs, commas, or spaces; text may be gzip-compressed.

Columns may appear in any order:

| Meaning     | Accepted names | Required |
|-------------+----------------+----------|
| Position    | ~base_pair_location~, ~position~, ~pos~, ~bp~, ~hm_pos~, ~chromStart~ | Yes |
| P-value     | ~p_value~, ~p~, ~pval~, ~pvalue~ | Yes |
| Chromosome  | ~chromosome~, ~chrom~, ~chr~, ~hm_chrom~, ~#chrom~ | Unless the file name supplies it |
| Variant ID  | ~rsid~, ~snp_id~, ~variant_id~, ~hm_rsid~, ~snp~, ~rs_id~ | No |
| Effect size | ~beta~, ~beta_value~, ~hm_beta~, ~effect_size~, ~b~ | No |

Chromosome names may include or omit the ~chr~ prefix. A ~chromStart~ column
uses BED-style, zero-based coordinates; every other position column uses
one-based coordinates. Positions must be whole numbers; scientific notation is
rejected because it may not identify the exact base. A p-value that underflows to
zero is preserved and shown above the chart's numeric scale.

* Built application files
~atlasforge build~ converts source files into the Parquet tables under ~<data-dir>/app/~.
These are implementation details of the API and should not be edited by hand.
Run the relevant build step again instead.

Large binary assets remain in their native formats:

| Source | Built location | Behavior |
|--------+----------------+----------|
| ~source/structure/models/~ | ~app/structure/models/~ | Copied and served locally |
| ~source/browser/coverage/~ | ~app/browser/coverage/~ | Copied and served with byte-range support |
| ~source/browser/transcripts.bed~ | ~app/browser/models.bb~ | bigBed read by byte range for the region in view |
| ~source/browser/gwas.parquet~ | ~app/browser/gwas/{study}.bb~ | One bigBed per study, with full-resolution variants and pyramid levels for wider views |

The static exporter copies these binary trees directly and renders the remaining
API responses as JSON.
