#+title: Source files

This page is for people who want to inspect, edit, or generate an atlas dataset
themselves instead of fully using the fetch pipeline. ~atlas fetch~ writes these
files to ~<data-dir>/source/~, and ~atlas build~ reads them. You can replace any
fetched file with your own as long as it follows the format below, then skip the
fetch step that normally creates it.

| File                 | Columns / format                                                                                               | Used by                |
|----------------------+----------------------------------------------------------------------------------------------------------------+------------------------|
| ~genes.tsv~          | id, symbol, name, chromosome, start, end, strand, length, alias, category, family, family_name, function_brief | gene tables            |
| ~transcripts.tsv~    | id, gene_id, name, type, start, end, length                                                                    | gene tables            |
| ~cds.fasta~          | FASTA keyed by gene id                                                                                         | clustering             |
| ~protein.fasta~      | FASTA keyed by gene id                                                                                         | clustering, structure  |
| ~expression.parquet~ | gene_id + one column per sample (Float32 TPM)                                                                  | clustering, expression |
| ~sample_tissue.tsv~  | sample_id, tissue, tissue_detail                                                                               | clustering, expression |
| ~orthologs.tsv~      | gene_id, species, target_gene_id, perc_id, perc_id_r1, perc_pos, orthology_type, ortholog_count                | conservation           |
| ~species.tsv~        | species, species_label, taxon_id                                                                               | conservation           |
| ~species_tree.nwk~   | Newick, leaves = species                                                                                       | conservation           |
| ~structure/~         | generated by the structure steps, not hand-authored (below)                                                    | structure              |
| ~browser/~           | generated by the browser steps, not hand-authored (below)                                                      | browser                |

* Structure files
Structure sources live in ~<data-dir>/source/structure/~. The pipeline starts with
~genes.tsv~ and ~protein.fasta~, matches each gene to UniProt, then gathers its features,
models, confidence scores, and experimental entries. Delete the structure directory to
fetch it again, or delete one file under ~models/~ to fetch only that model again.

| File               | Columns / format                                                                                                                                                                                                                              |
|--------------------+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| ~uniprot_map.tsv~    | gene_id, symbol, uniprot_accession, uniprot_id, uniprot_length, seq_agreement, id_route                                                                                                                                                       |
| ~features.tsv~       | gene_id, uniprot_accession, feature_type, start, end, description, ligand_name, ligand_chebi, ligand_label                                                                                                                                    |
| ~structures.tsv~     | gene_id, uniprot_accession, afdb_entry_id, afdb_version, model_url, ..., alphafill_page_url                                                                                                                                                   |
| ~experimental.tsv~   | gene_id, uniprot_accession, pdb_id, method, resolution, coverage, chains, ligand_ccd, ...                                                                                                                                                     |
| ~sequences.tsv~      | gene_id, uniprot_accession, sequence, the UniProt canonical sequence the topology figure numbers residues by                                                                                                                                  |
| ~confidence.parquet~ | gene_id, uniprot_accession, plddt (one 0-100 score per residue). A gene appears here only when AlphaFold's model is built from the UniProt canonical sequence, because scores belonging to any other sequence cannot be placed on the figure. |
| ~models/~            | one binary-CIF file per accession, only under ~--download-predicted~; experimental entries mirror the same way into ~models/pdb/~ under ~--download-experimental~                                                                                   |

Manual changes to the gene to UniProt mapping belong in ~uniprot_overrides.tsv~
under the curation directory, not in ~uniprot_map.tsv~, which is regenerated.

~atlas build~ copies whatever it finds under ~models/~ into
~<data-dir>/app/structure/models~, which is the copy the running app serves.
Anything you did not mirror is streamed live from AlphaFold DB or RCSB instead.
For the 462-gene SLC dataset, it's around 93 MiB of predicted models and about
591 MiB of experimental entries, which can increase a static export from roughly
12 MiB to roughly 763 MiB.

* Genome browser files
Browser sources live in ~<data-dir>/source/browser/~. The pipeline keeps the same genomic
window from every source. Each window contains a gene and a flank on both sides. The flank
is based on the gene's length, limited by ~--browser-flank-min~ and
~--browser-flank-max~, and each complete window is at least 200 kb wide. With the defaults,
the 462-gene SLC dataset covers 135 Mb, or about 4% of the genome.

| File                | Columns / format                                                                                                                       |
|---------------------+----------------------------------------------------------------------------------------------------------------------------------------|
| ~transcripts.bed~   | BED12, no header, ~name = transcript_id___gene_id___biotype___gene_name~. ~thickStart~/~thickEnd~ carry the coding part, and are equal when there is none |
| ~chroms.tsv~        | chrom, size, role (~primary~, ~alt~, or ~unplaced~). Chromosomes are spelled the way the gene models spell them, and only primary ones are drawn |
| ~gene_models.tsv~   | source, kind, version, assembly, retrieved_date, license_spdx, url, detail, where detail records the flanks the windows were cut at     |
| ~coverage.tsv~      | track_id, label, group, strand, source, origin_url, bin, local, chroms, size_mismatch, source_bytes, window_bytes. ~window_bytes~ is what a local copy would cost, estimated before it is written |
| ~coverage/~         | one sliced bigWig per track, ~<track_id>.bw~ or ~<track_id>.plus.bw~ and ~<track_id>.minus.bw~, written only under ~--slice-coverage~     |
| ~gwas.parquet~      | study_id, chrom, position, snp_id, p_value, beta, already cut to the windows                                                           |
| ~gwas_studies.tsv~  | study_id, trait, citation, source, assembly, license_spdx, url, retrieved_date, n_variants, chroms                                      |

Coverage remains in bigWig format. The browser reads only the byte ranges it needs, so the
same file works at every zoom level without a dedicated data server. A track with ~local~
set to ~no~ is read from its original URL and adds nothing to a static export. That server
must support byte-range and cross-origin requests; ENCODE supports both. A track set to
~yes~ is sliced into ~coverage/~ and copied to ~<data-dir>/app/browser/coverage~.

Slicing keeps local copies small. In this dataset, an 867 MiB ATAC-seq track becomes 38 MiB,
and a 4.0 GiB RNA-seq track becomes 25 MiB. ~--browser-bin~ sets the finest resolution to
keep, rather than a fixed bin size. If a track already uses longer runs, the pipeline keeps
its original resolution. Before writing any files, ~atlas fetch~ shows the estimated total
size and stops if it exceeds ~--browser-max-bytes~.

* Curation files
The first ~atlas fetch~ creates these files in ~--curation-dir~, which defaults to
~<data-dir>/curation~. Later runs leave them alone. Review them before continuing the
fetch: they hold the naming, exclusions, and other choices that public sources cannot make
for your atlas.

| File                    | What you decide with it                                             |
|-------------------------+---------------------------------------------------------------------|
| ~families.tsv~          | group_name, family_key, display_name per family, with "# also:" lines listing the alternate names to pick from |
| ~exclusions.txt~        | approved symbols to drop, one per line, ~#~ comments allowed        |
| ~symbol_overrides.tsv~  | gene_id, approved_symbol, display_symbol, to show a gene under an alias |
| ~species.tsv~           | the species to compare against, and their names in each source      |
| ~uniprot_overrides.tsv~ | hand fixes to the gene → UniProt accession mapping                  |
| ~browser_tracks.tsv~    | the coverage tracks the browser draws, each an ENCODE accession, a URL, or a path |
| ~browser_gwas.tsv~      | the GWAS studies the browser draws, each a GWAS Catalog accession or a path |
